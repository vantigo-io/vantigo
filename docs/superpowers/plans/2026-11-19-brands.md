# Brands — implementation plan

Date: 2026-11-19. Design: `docs/superpowers/specs/2026-11-19-brands-design.md` (rules
**B1–B35**, cited below). Research: `docs/superpowers/research/2026-11-18-dark-theme-and-brands.md`
(§3, and the owner's decisions in §6).

Six deliveries, each mergeable on its own, with tests and demo seed data:

| # | Delivery | Needs |
| --- | --- | --- |
| **B-A** | One editable default brand: tables, logo pipeline, public assets, runtime theme, pre-paint, the editor, the env import, the permission | D-A (PR #383) merged |
| **B-B** | Several brands, rules, resolution, the personal choice, "who sees what", the live topic | B-A |
| **B-C** | Sign-in branded by e-mail domain | B-B |
| **B-D** | Campaigns | B-B |
| **B-E** | Brands on documents: customers, invoices, orders | B-B (not B-C or B-D) |
| **B-L** | The landing-site claim, in vantigo-landing | the user guide of B-A and B-B merged |

B-C, B-D and B-E are independent of each other once B-B has landed and can run in
parallel. Each delivery is a branch off the latest `main`, one PR, per the repository's
stacked-PR practice when one builds on an unmerged other.

## Ground rules for every delivery

- **Migration numbers are claimed at merge time.** `mig/` is at 00205 on the D-A branch
  and 00203 is a gap, so the next number is not knowable now; parallel stacks have
  collided before. Write the file with the next free number, and **right before merging**
  look at main's latest, renumber in-history if needed (rebase `--exec`, re-signing with
  `-S`), and let CI run again.
- **Documentation is its own step** in each delivery and lands in the same commit series
  (AGENTS.md). Bilingual pages in `en/` and `nb/` with the same file names; write English
  first, then translate. After any docs edit, run `go generate ./...` in `apps/server`
  (the assistant embeds the docs; skipping it fails Go lint and tests).
- **Gates before "done":** `mise run server:check`, `mise run server:test`,
  `mise run frontend:check`, `mise run docs:check`. Conventional Commits, signed.
- **No new module**, so the "Adding a module" registries are untouched. Identity gains a
  permission, a live topic and two contract slots (`contracts.BrandTargets`,
  `contracts.Brands`); each is declared in `module.Module`, resolved in Compose
  (`srv/module/compose.go`) and covered by `module-boundaries.md`.
- **Tests that exist must keep passing unchanged** where a rule says "untouched"
  (notably `TestNewIndex_ScriptHashCoversExactlyTheInjectedScript`, and Invoices'
  logo tests).
- **Browser check** at the end of B-A, B-B, B-C and B-E in both colour schemes and with a
  non-default brand, recorded in the PR. `srv/` is `apps/server/internal/`, `host/`
  `apps/host/frontend/src/`, `shell/` `packages/frontend-shell/src/`.

## B-C: sign-in branded by e-mail domain

Branch `feat/brands-c`. Rules B25, B26 and the privacy note.

### Files and areas

- `srv/identity/brand_public.go`: `GET /brand/public?domain=` gains the domain lookup over
  published `domain` rules (an indexed read on the unique domain target), a global
  ceiling policy beside the per-address one, `Cache-Control: public, max-age=300`,
  `Vary` correct, domain normalisation shared with the rule validator.
- `host/routes/sign-in.tsx`, `forgot-password`, `reset-password`, `accept-invitation`:
  a `useDomainBrand(email)` hook in `shell/brand` (valid-looking domain, 400 ms idle or
  blur, one request per distinct domain, in-memory cache), the cross-fade (CSS
  transition on the root variables; `prefers-reduced-motion` honoured), the wordmark or
  light/dark mark by scheme, the title.
- The sign-in page logo (today only the title): mark above the form.
- `localStorage["vantigo-brand-public"]` mirrors the last matched brand so a returning
  visitor's first paint is that brand (extending B16's snippet with a second key, read
  only on public routes).

### Migrations

None, if B-B's unique index on domain targets is sufficient; add one only if the review of
the lookup's query finds a missing index.

### Tests

- **Go:** matched domain answers the brand, unmatched answers the default with
  `matched: false`, draft and archived brands never answer; **the answer for a given
  domain is byte-identical whatever local part the client had** (the server only ever
  receives the domain; assert the handler ignores any other parameter and that the same
  request twice is the same), and does not vary with whether any user has an account on
  the domain (a domain with users and one without, attached identically, answer
  identically); rate limit (the 31st request in a minute is 429 with `Retry-After`; the
  global ceiling); case and punycode normalisation; an over-long or invalid domain is 400.
- **Frontend:** typing a matching address fades in once, an edit back to a non-matching
  domain fades out, one request per distinct domain, debounce and blur, reduced motion
  changes instantly, a 429 keeps the current brand, sign-in still works when the lookup
  fails.
- **Security review** (a separate pass, per the execution protocol): no enumeration of
  accounts; the endpoint does not reflect its input into HTML or headers.

### Seed data

Uses B-B's `nordlys.example` rule; the README/CONTRIBUTING seed notes list the demo
address (`anna@nordlys.example`) that shows the fade.

### Documentation (its own step)

## Order and parallelism

```
D-A (#383) ─ B-A ─ B-B ─┬─ B-C ──┐
                        ├─ B-D ──┼─ B-L (extended as each lands)
                        └─ B-E1 → E2 → E3
```

- Do not start B-A before D-A has merged: it edits `theme.ts`, `theme.css` consumers and
  `colorSchemeScript`.
- Run B-C, B-D and B-E in parallel worktrees; they touch different files, except the
  shared `openapi/identity.yaml` and `host/i18n.ts`, which rebase cleanly if each delivery
  appends its own section. Rebase onto the latest `main` right before merging, and let CI
  run again.
- Each delivery is merged by its author after green PR CI (the merge queue does not gate on
  CI by itself; wait for the checks).
