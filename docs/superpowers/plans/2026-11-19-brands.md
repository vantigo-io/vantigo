# Brands — implementation plan

Date: 2026-11-19. Design: `docs/superpowers/specs/2026-11-19-brands-design.md` (rules
**B1–B35**, cited below). Research: `docs/superpowers/research/2026-11-18-dark-theme-and-brands.md`
(§3, and the owner's decisions in §6).

Seven deliveries, each mergeable on its own, with tests and demo seed data:

| # | Delivery | Needs |
| --- | --- | --- |
| **B-A0** | The pure library: shade scale and contrast in Go and TypeScript, the golden file, and the extraction of the invoices logo validation into a shared package | nothing (not even D-A) |
| **B-A** | One editable default brand: tables, logo assets, the brand stylesheet, runtime theme, the editor, the env import, the permission | B-A0, and D-A (PR #383) merged |
| **B-B** | Several brands, rules, resolution, the personal choice, "who sees what", the live topic | B-A |
| **B-C** | Sign-in branded by e-mail domain | B-B |
| **B-D** | Campaigns | B-B |
| **B-E** | Brands on documents: customers, invoices, orders | B-B (not B-C or B-D) |
| **B-L** | The landing-site claim, in vantigo-landing | the user guide of B-A and B-B merged |

**No delivery depends on a later one, and each tests only its own side:** B-D and B-E
use a fake `contracts.Brands` where they need a brand, and never import another
delivery's tests. B-C, B-D and B-E are independent of each other once B-B has landed and can run in
parallel. Each delivery is a branch off the latest `main`, one PR, per the repository's
stacked-PR practice when one builds on an unmerged other.

## Ground rules for every delivery

- **Migration numbers are claimed at merge time.** `mig/` is at 00205 on the D-A branch
  and 00203 is a gap, so the next number is not knowable now; parallel stacks have
  collided before. Write the file with the next free number, and **right before merging**
  look at main's latest, renumber in-history if needed (rebase `--exec`, re-signing with
  `-S`), and let CI run again.
- **Documentation is its own step** in each delivery and lands in the same commit series
  (AGENTS.md). Bilingual pages in `en/` and `nb/` with the same file names; write English
  first, then translate. After any docs edit, run `go generate ./...` in `apps/server`
  (the assistant embeds the docs; skipping it fails Go lint and tests).
- **Gates before "done":** `mise run server:check`, `mise run server:test`,
  `mise run frontend:check`, `mise run docs:check`. Conventional Commits, signed.
- **No new module**, so the "Adding a module" registries are untouched. Identity gains a
  permission, a live topic and two contract slots (`contracts.BrandTargets`,
  `contracts.Brands`); each is declared in `module.Module`, resolved in Compose
  (`srv/module/compose.go`) and covered by `module-boundaries.md`.
- **Tests that exist must keep passing unchanged** where a rule says "untouched"
  (notably `TestNewIndex_ScriptHashCoversExactlyTheInjectedScript`, and Invoices'
  logo tests).
- **Observability (B39):** each delivery that adds an endpoint or a worker step adds its
  counters and info logs, and a test that they move.
- **Browser check** at the end of B-A, B-B, B-C and B-E in both colour schemes and with a
  non-default brand, recorded in the PR. `srv/` is `apps/server/internal/`, `host/`
  `apps/host/frontend/src/`, `shell/` `packages/frontend-shell/src/`.

## B-A0: the pure library

Branch `feat/brands-a0`. Rules B3, B4 (the maths), B6 (the extraction). No behaviour a user
can notice, so its commit carries `Docs-Impact: none — pure library and refactor, no
behaviour change` (or, if the extraction touches Invoices' documented limits, a one-line
note in `reference/invoices.md`).

### Files and areas

- `srv/identity/brandscale.go`: sRGB ↔ linear ↔ OKLab ↔ OKLCH with the matrices of B3, the
  gamut search (24 iterations, lower bound), `Scale(hex)`, `FilledText`, the WCAG contrast
  function and the pair checks of B4. The page, card and text colours are constants in
  `brandscale_tokens.go`, and a test reads `packages/frontend-shell/src/theme.css` and
  fails if they differ.
- `packages/frontend-shell/src/brand/scale.ts`: the TypeScript port with the same
  constants.
- **The golden file at one fixed path both suites read:**
  `packages/frontend-shell/src/brand/brand-scale.golden.json` (the Go test opens it by
  its relative path from the module root). Ten inputs including `#4f46e5`, one near each
  end of the lightness range, and one near-grey.
- The shared logo package (a name under `srv/` decided in the PR; it imports no business
  module): `judgeLogo`, `readLogo`, the re-encoding and the bounds moved out of
  `srv/invoices/logo.go`. Invoices imports it; behaviour and codes unchanged.

### Migrations / seed data

None.

### Tests

The properties of B3 (shade 6 exact; strictly decreasing lightness; hue within 2°; in
gamut; `filledText` flips at the threshold; `brand_primary_range` bounds) and the golden
file in **both** languages; the contrast pairs and the suggested nearest passing primary;
**Invoices' existing logo tests pass unchanged** against the shared package, plus the
package's own tests (including the square check, which the icon uses).

### Documentation (its own step)

None to publish. `go generate ./...` is not needed (no docs change); `docs:check` passes
through the `Docs-Impact: none` trailer.

### Landing step

None.

### Tests

- **Go, unit:** the brand version type's validation; **support fields** (B37):
  `javascript:`, `//host`, a backslash-host path, a relative path without a leading `/`,
  an address with a display name, a phone with letters and a 31-character phone are each
  `brand_support_invalid`, and the accepted forms equal `config`'s; a request carrying
  `tokens`, `shades` or the derived set is 400, and the JSON import recomputes tokens
  whatever it carries (a doctored import cannot set a colour); `filledText` and the
  derived-variable set (B36).
- **Go, handlers (`modtest`):** create-at-mount with no env, with env title, with env
  support, with a logo URL fetched from a test server, with an unreachable one (rest
  imported, notice raised), with no object storage; **the import refuses a private,
  loopback, link-local and cloud-metadata address** (`127.0.0.1`, `10.0.0.5`,
  `169.254.169.254`, `[::1]`, and a hostname that resolves to one, through the injected
  resolver) and a redirect to one, and a body past 2 MiB; a slow host does not delay
  `Mount` (the test asserts mount returns while the fetch is blocked); **two replicas
  mounting at once create one default brand** (a concurrent test over the unique partial
  index) and only one runs the import; the env stays injected into the index until
  `imported_env_at` is set, and is dropped after (the rollback story); publish refused on a failing pair
  (`brand_contrast`) and on `brand_primary_range`; `If-Match` conflict; draft vs published
  isolation (a draft is invisible to `GET /brand`, visible to `?preview=` for
  `identity:brands` and refused for anyone else); the assets route answers a published
  logo, 404s a draft's, sets `immutable` and is rate-limited;
  `GET /brands/{id}/logos/{slot}?draft=true` streams a draft logo to `identity:brands` and
  is refused to anyone else; a logo `PUT` changes the draft only; anonymous
  `GET /brand/public`; **`GET /brand.css`**: the default brand's variables with no session,
  the user's own brand with a session cookie, an `ETag` and `Vary: Cookie`, `private` with a
  session, never one person's brand to another (two users, two requests), and a valid CSS
  body built only from generated values (no user-controlled string reaches it);
  the permission: Owner passes, a role with `identity:brands` passes, another role gets 403;
  the audit rows.
- **Go, web:** `TestNewIndex_ScriptHashCoversExactlyTheInjectedScript` passes untouched;
  the index carries the stylesheet `<link>` under a base path; a new test for the extended
  snippet (the fallback applies a stored brand only when the stylesheet's marker variable
  is missing, ignores a mirror of another user or a higher `v`, sets the title; survives a
  throwing `localStorage`); the injected config keeps the env keys before the import and
  drops them after.
- **Frontend:** `createVantigoTheme` (default brand = today's theme exactly: assert
  equality with `vantigoTheme`); **a test with a non-default brand** asserts that
  `--vantigo-link`, `--vantigo-subtle-bg` and every Mantine derived variable follow it and
  equal the server's set for the golden brands (B36); `BrandProvider` fetch, the mirror
  (cleared on sign-out, ignored for another user); the shell's logo choice by scheme; the editor
  (contrast table, fix button, preview in both schemes, upload errors); permission gating of
  the route. The existing `matchMedia` mock stays `matches: false`.
- **Config:** the `Branding` fields still parse for the import and are otherwise ignored
  once it has run; a boot log line names ignored variables.
- **Observability:** the import's outcome and the stylesheet's cache hits are counted.

### Tests

- **Go, resolution (table-driven, the heart of the delivery):** first match wins and
  respects the dragged order; domain exact match and not subdomain (`mail.acme.no` does not
  match `acme.no`); a disabled group or a membership forced out does not match
  (`membership_override`); a legal entity in force today, ended, future-dated, archived,
  with two employments in two entities; Staff disabled (entity rules inert, others work);
  the choice beats rules, is ignored when it stops being a candidate, `choiceIgnored`
  reported; integration and agent users get the default; a person in no rule gets the
  default; candidates are the union of matching rules plus default.
- **Go, lookup and switch:** `GET /brands/resolution` returns the matched rule and brand
  and **no employment detail** to a caller with only `identity:brands`, and the fuller
  explanation to one who also holds the Staff permission; `PUT /account/brand` with a
  non-candidate is `409 brand_not_candidate`; the default is a candidate only when no rule
  matched; **erasure**: anonymising a user keeps `preferred_brand_id`, and deleting a brand
  nulls it (`ON DELETE SET NULL`); the identity erase code is checked for a column list.
- **Go, rules API:** duplicate `(kind, target)`, a domain taken by another brand
  (`domain_taken`), a rule pointing at an archived brand refused, stale `If-Match`
  refused, whole-list replace is atomic.
- **Go, contract and boundaries:** Staff's provider against a seeded dataset;
  depguard/schema tests still pass (identity does not import Staff).
- **Go, live:** `modtest`/live harness test that a publish and a rule change notify
  `identity.brand` on commit and not on rollback, for publish, make default, archive,
  restore, delete, rules and campaigns; a personal switch notifies only the keyed topic;
  `Authorize` admits a signed-in person (the keyed topic only their own id) and refuses
  anonymous; the per-user resolution cache (30 s) is invalidated by those events, and a
  burst of 200 simultaneous `GET /brand` after a publish makes at most one Staff call per
  user.
- **Frontend:** drag ordering produces the expected list; the lookup panel; the switcher
  shows only with several candidates and saves; a live event triggers one refetch and a
  repaint; permission gating.
- **Integration:** `apps/server/internal/integration` — a second user in a different
  group resolves to a different brand end to end.

## B-C: sign-in branded by e-mail domain

Branch `feat/brands-c`. Rules B25, B26 and the privacy note.

### Files and areas

- `srv/identity/brand_public.go`: `GET /brand/public?domain=` gains the domain lookup over
  published `domain` rules (an indexed read on the unique domain target), a
  per-address `ratelimit.Policy` (30 per minute; the limiter is per address only, so no
  global ceiling), the valid-looking-domain check of B25 (one dot, final label of 2+
  letters, else `400 domain_invalid`), counters and info logs with the domain's hash
  (B39), `Cache-Control: public, max-age=300`,
  `Vary` correct, domain normalisation shared with the rule validator.
- `host/routes/sign-in.tsx`, `forgot-password`, `reset-password`, `accept-invitation`:
  a `useDomainBrand(email)` hook in `shell/brand` (valid-looking domain, 400 ms idle or
  blur, one request per distinct domain, in-memory cache), the cross-fade (CSS
  transition on the root variables; `prefers-reduced-motion` honoured), the wordmark or
  light/dark mark by scheme, the title.
- The sign-in page logo (today only the title): mark above the form.
- A returning visitor's first paint on a public page is the default brand from the
  stylesheet (B16); the matched brand arrives with the first lookup. No second
  localStorage key (the sign-in page must not remember a domain's brand across users).

### Migrations

None, if B-B's unique index on domain targets is sufficient; add one only if the review of
the lookup's query finds a missing index.

### Tests

- **Go:** matched domain answers the brand, unmatched answers the default with
  `matched: false`, draft and archived brands never answer; **the answer for a given
  domain is byte-identical whatever local part the client had** (the server only ever
  receives the domain; assert the handler ignores any other parameter and that the same
  request twice is the same), and does not vary with whether any user has an account on
  the domain (a domain with users and one without, attached identically, answer
  identically); rate limit (the 31st request in a minute from one address is 429 with
  `Retry-After`); case and punycode normalisation; `localhost`, `a.b-`, a single label and
  an over-long domain are `400 domain_invalid`; the counters and the hashed-domain log line.
- **Frontend:** typing a matching address fades in once, an edit back to a non-matching
  domain fades out, one request per distinct domain, debounce and blur, reduced motion
  changes instantly, a 429 keeps the current brand, sign-in still works when the lookup
  fails.
- **Security review** (a separate pass, per the execution protocol): no enumeration of
  accounts; the endpoint does not reflect its input into HTML or headers.

### Seed data

Uses B-B's `nordlys.example` rule; the README/CONTRIBUTING seed notes list the demo
address (`anna@nordlys.example`) that shows the fade.

### Documentation (its own step)

- `{en,nb}/admin/branding.md`: **Sign-in by e-mail domain**: attaching a domain, that

## Order and parallelism

```
B-A0 ─┐
D-A (#383) ─┴ B-A ─ B-B ─┬─ B-C ──┐
                        ├─ B-D ──┼─ B-L (extended as each lands)
                        └─ B-E1 → E2 → E3
```

- B-A0 can start now; it only reads `theme.css`.
- Do not start B-A before D-A and B-A0 have merged: it edits `theme.ts`, `theme.css` consumers and
  `colorSchemeScript`.
- Run B-C, B-D and B-E in parallel worktrees; they touch different files, except the
  shared `openapi/identity.yaml` and `host/i18n.ts`, which rebase cleanly if each delivery
  appends its own section. Rebase onto the latest `main` right before merging, and let CI
  run again.
- Each delivery is merged by its author after green PR CI (the merge queue does not gate on
  CI by itself; wait for the checks).
