# Entra phase 1, delivery C — the module: implementation plan

> **For agentic workers:** implement this plan task by task, one implementer per task and a reviewer after it, never in the same context. Tasks 3 and 4 get a security-focused reviewer (a tenant-wide application credential, a Temporary Access Pass, and a client that reaches the network). Steps use checkbox (`- [ ]`) syntax for tracking. No agent commits; the coordinator commits per task group.

**Goal:** the `entra` module — Microsoft Entra ID as the first provider in the slot delivery B built. An Owner registers the tenant and the client, adds client secrets in the plural, and runs the connection test; `entra:manage` sets the account rules; and the module's `contracts.IdentityProvisioner` executes Staff's decisions against the tenant through a guarded Graph client: finds or creates the user disabled with the mapped attributes and a legal UPN, enables them on the day with the hire date, the licences and a Temporary Access Pass kept sealed and shown once, keeps them in step, disables them with the sessions revoked, the leave date written, the direct licences stripped and the groups left as the connection says, and soft-deletes them when Staff asks. The wizard on the module's tile carries every portal step, embedding identity's Single sign-on forms as its last two. A fake Graph proves it; a tagged test against a real tenant settles the research's three uncertain facts.

**Architecture:** a new module `apps/server/internal/entra` (schema `entra`, `openapi/entra.yaml`, `apps/entra/frontend` as `@vantigo/entra-ui`, the tile **Microsoft Entra ID**), depending on nobody but identity for what it reads (nothing, in C: the Owner's and `entra:manage`'s checks are the router's) and writing nothing outside its schema; it fills `Module.IdentityProvisioner` (built by `Compose` and `Workers` alike, stateless but for the process-wide transport and the token cache). The host's wizard route hands identity's `SsoSettingsCard` into the page for steps 5 and 6. Branch `feat/entra-module`, cut from `main` at `503459bf` (B merged), the PR against `main`. **One migration**, `00061_entra_baseline.sql` (00060 is the highest on main), with its pin test. `MODULES` gains `entra`, which requires `staff`. No worker of its own: Staff's accounts worker is the one that calls the provider. Groups (D9, D10, D14) are delivery D's: the four group methods answer `ErrGroupNotManageable` and `GroupTraits` the declaration of the two traits C can already name (`type`, `mailNickname`), so Staff's group page in D has something to render.

**Spec:** [`docs/superpowers/specs/2026-10-19-entra-design.md`](../specs/2026-10-19-entra-design.md) D11, D12, D13, D15, the deliveries table (C), testing (C), readings 5, 6, 8, 9, 11; the research [`2026-10-19-entra-module.md`](../research/2026-10-19-entra-module.md) §3.1–3.6 (Graph's users, licences, the pass, throttling, the permissions), §7.5 (the wizard's six steps), §9 (the test tenant); delivery B's plan [`2026-10-20-staff-provisioner-slot.md`](2026-10-20-staff-provisioner-slot.md) for what Staff expects of a provider (its reading 2, `Key()`; the reasons Staff raises as items: `secret_expiring`, `secret_expired`, `credential_invalid`, `role_missing`; the bound on every code).

**Pattern code:** `internal/contracts/identity_provisioner.go` (the contract, verbatim); `internal/modtest/identity_provisioner.go` (the fake's behaviours, which the real provider must match where the contract is silent: `Created`, `HasPass`, the pass's single reveal); `internal/calendar/subscriptions_fetch.go:60-125` (`guardedTransport` — copied, never imported, with keep-alives **on**); `internal/peppol/lookup.go` (the same guard with a resolver seam); `internal/customers/brreg_test.go` (`fakeBrregTransport`: an `http.RoundTripper` fake wired through `modtest.WithTransport`); `internal/invoices/credentials.go` (a sealed credential under its own purpose, never answered); `internal/identity/sso_settings_owner.go` and `openapi/identity.yaml`'s `/owner/sso` operations (`policy:OwnerManagement`, `If-Match` on a version, the audit without the secret); `internal/identity/system.go:28-62` (a short cache's shape, if the token cache wants one); `internal/calendar/module.go`, `server.go`, `errors.go`, `main_test.go`, `harness_test.go` (the newest module's skeleton: `contracttest.NewForModule`, `RequireCoverage`, the problem type); `internal/payments/vipps/vipps_test_env_test.go` (a tagged test's shape: the build tag, the `*_TEST_*` variables, skipped without them, a status log); `docs/superpowers/plans/2026-10-19-calendar-foundation.md` task 2 (every shared file a module's skeleton touches) and `en/contributing/module-boundaries.md` §"Adding a module"; `apps/calendar/frontend` (the package shape), `apps/host/frontend/src/routes/calendar.tsx` and `routes/calendar/index.tsx` (the host's route for a module page), `apps.ts`/`apps.test.ts`/`navigation.ts`/`catalogs/*` (the registry), `routes/workspace/-sso-settings.tsx` (`SsoSettingsCard`, to be given `defaults` and `sections` props).

## Exact values

- Hosts: `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token`, scope `https://graph.microsoft.com/.default`; `https://graph.microsoft.com/v1.0`. ## Readings of the spec

1. **The fake Graph lives in the module** (`internal/entra/graphtest`), not in `modtest`: it is Entra's shape alone, no other module's test needs it, and a module may import its own subpackage; `modtest.WithTransport` wires it as the design's "through the transport, not a base URL".
2. **`Provider(ctx)` reads the row and nothing else**, so Staff's `GET /meta`, which asks it live, costs no network call; the status is written by the connection test and by the lifecycle's failures.
3. **Groups answer `ErrGroupNotManageable` in C**; `GroupTraits` already names `type` and `mailNickname` so D's form has a declaration to render. The leaver's `all` removes the person from every non-dynamic, non-role-assignable group the directory lists, groups the module never made included — D13's rule, in C.
4. **`role_missing` is a streak.** A sensitive 403 cannot say whether the target is privileged or the app lacks the User Administrator role; the account reports `privileged` either way, and the connection reads `role_missing` once three sensitive actions in a row were refused with none succeeding since, which is what "every account fails it" means in practice.
5. **The pass delivery setting is stored and offered, the manager's notice is not sent in C**: D13 makes the notice Staff's through `Users.Notify`, but the contract gives Staff no way to read `pass_delivery`; a later delivery adds `ProviderInfo.PassDelivery` (or an equivalent) and the notice together, so the setting means something before Staff acts on it.
6. **`Account` answering nil leaves the row**: Staff records `user_gone` and never re-creates; the module keeps the row for the events' sake, marked nothing.
7. **The Owner-only steps are the host's session's to hide**: the module's page shows steps 1–3 read-only to `entra:manage` holders who are not Owners, and the server refuses their writes regardless.
