# Cutover — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Delete the .NET tree and its tooling, rewrite the manifests and docs, and leave `ghcr.io/vantigo-io/vantigo` built from `apps/server`.

**Architecture:** Deletion first, in one commit that also repairs the pre-commit hook and CI so the tree never sits broken. Then the manifest, then the docs, which are separable on purpose — if the deletion goes wrong, the documentation rewrite should not be entangled with it.

**Tech Stack:** Go 1.27, Bun workspaces, Husky v9, GitHub Actions, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-14-cutover-design.md`

## Global Constraints

- **The Go suite is the baseline:** from `apps/server`, `go test ./... -count=1` under `taskset -c 0-3` — 32 packages ok. Frontend baseline: `bun run frontend:test` → 67 files / 306 tests.
- **Six ways a check here reports success having verified nothing.** `go`/`sqlc`/`golangci-lint`/`shellcheck` are not on PATH bare (prefix `mise exec --`); an exit code captured after a pipe reports the pipe's status (use `PIPESTATUS[0]`); `golangci-lint run` from the repo root prints `0 issues.` beside a typechecking error (run it from `apps/server`); bare `shellcheck` exits 127; `bun --cwd X run test` prints a usage banner and exits 0 having run nothing (correct form: `bun run --cwd X test`); and `bun run format:check` fails bare on an unrelated dotnet SDK mismatch but passes via `mise exec --` — **that last one disappears with this sub-project.**
- **Print tool versions AND the working directory in the same command as every check.** The workspace pins Bun 1.3.14; bare `bun` resolves elsewhere.
- **Never `--no-verify`. Never force-push.** The pre-commit hook is the thing being modified — respect it.
- **Deletion is the one irreversible-feeling act here, and it is not:** everything removed stays in git history. Do not preserve dead code "just in case"; that is what the history is for.

### Task 1: Delete the .NET tree, and repair what depended on it

**Delete:** `apps/{communications,customers,energy,host,identity,products}/backend/**`, `orchestration/AppHost/**`, `packages/{architecture,azure-identity,configuration,contract-recording,contracts,dataprotection-postgresql,storage,tenancy}/**`, `Vantigo.slnx`, `global.json`, `.bun-version`, `tools/toolchain/**`, and the six files spec §1.1 adds: `.config/dotnet-tools.json`, `GitVersion.yml`, `Directory.Packages.props`, `Directory.Build.props`, `Directory.Build.targets`, `Directory.Solution.targets`.

**Every `apps/*/frontend/` directory stays.** Only the `backend/` siblings go.

**Repair in the same commit — the tree must never be left broken:**
- `.husky/pre-commit` — remove the `dotnet format` lines (spec D1). It is `set -e`, and `gofmt` runs *after*, so leaving them blocks every commit and skips the Go check.
- `package.json` — `format:check`, `format:write` drop `dotnet format`; `toolchain:check`/`toolchain:test` go with `tools/toolchain`.
- `mise.toml` — drop the `dotnet` pin and the `global.json` comment.
- `.github/workflows/ci.yml` — delete `build_and_test_solution`, `dotnet tool restore` in `metadata`, both `dotnet publish` steps, the `csharp` CodeQL matrix entry.

**Teeth:** introduce a Go formatting violation and confirm the pre-commit hook still rejects the commit. A hook that runs less looks exactly like a hook that passes.

### Task 2: Fold the Go workflows into the main pipeline

`server-ci.yml`, `server-release.yml` and `server-test.yml` were written to merge here. `ci.yml` must end up building and publishing `ghcr.io/vantigo-io/vantigo` from `apps/server` via `scripts/build-artifacts.sh` + `scripts/build-image.sh`, with versioning from `svu` rather than the deleted GitVersion.

Report what the image tag is derived from before and after — that is the thing most likely to break silently.

### Task 3: Rewrite the deployment manifest, and make its guard real

`deploy/compose/compose.yaml`: `ConnectionStrings__vantigo` → `DATABASE_URL`; `healthcheck.test` → `["CMD", "/app/vantigo", "healthcheck"]`; env keys to the Go names in `internal/config/config.go`.

**Probes use the exec form** — `internal/security/hostfilter.go:17` allows APP_URL's host plus loopback, so an `httpGet` probe sending the pod IP as `Host` is rejected. Termination grace period ≥ 35 s (`SHUTDOWN_TIMEOUT` defaults to 30 s).

**Add a real guard to `validate_compose`** (spec D2): assert the manifest contains no `Vantigo.Host` and no `ConnectionStrings__`. `docker compose config -q` checks syntax only, so today this file could be entirely wrong with a green pipeline.

Also rewrite `deploy/compose/README.md`, `.env.example`, `vantigo.env.example`.

**Teeth:** reintroduce `ConnectionStrings__vantigo`; the new CI assertion must fail.

### Task 4: Switch the dev proxy and remove the CSRF no-op

`apps/host/frontend/vite.config.ts:8` — the Aspire fallback `http://localhost:10010` points at a closed port once AppHost is gone; `mise run server:dev` serves `:8080`.

`ensureCsrfToken`/`X-XSRF-TOKEN` is **public API** of `packages/frontend-api-client` (`src/index.ts:23,120,150,187`) across 21 files — removing it changes every consumer. Frontend baseline 67 files / 306 tests must hold.

### Task 5: Delete three docs, rewrite `docs/README.md`

**Delete** `docs/tenancy.md`, `docs/data-protection-key-wrapping.md`, `docs/azure-identity.md` (spec D4 — no tenancy, no persisted key ring, no Azure anywhere in `apps/server`). Update the index and every inbound link.

### Task 6: Rewrite `README.md` and `CONTRIBUTING.md`

**`CONTRIBUTING.md:255-511` is already accurate for Go — copy from it, do not re-derive.** Replace the `dotnet`/Aspire bootstrap with `mise install` + `mise run server:dev`. Document all six commands from `cmd/vantigo/main.go`'s header comment.

Three corrections that are not renames: **`api` mode migrates before serving** (spec D5); the corpus at `openapi/testdata/exchanges/` is **unregenerable** once .NET is gone, so `CONTRIBUTING.md:345-352` must stop describing how to refresh it (spec D6); and `CONTRIBUTING.md:523` claims lint-staged when the hook is a plain unconditional script.

Add one line: `.cs` paths in Go comments refer to the pre-cutover tree, in git history (spec D7).

### Task 7: Rewrite the remaining operator docs

`communications.md`, `customers-authentication.md`, `module-boundaries.md`, `products.md`, `sso-scim-operations.md`, `storage.md`, `transport-security.md`.

**Write from the code.** `internal/config/config.go`'s field comments are the authoritative env reference; translating `Section__Key` to `SCREAMING_SNAKE` by hand invents keys that do not exist.

Known substantive divergences, not renames: `MODULES` is a positive allowlist, not per-module booleans; Go infers OIDC client-auth mode from which credential is set rather than an explicit switch; SCIM has no file-based token variant; `TRUSTED_PROXY_HOPS` counts hops rather than listing proxies; **storage is fs-only** — state the regression plainly; per-channel SMTP is API-managed and sealed via `internal/secrets`, not env vars.

Keep what is already right: `transport-security.md`'s fail-closed policy (Go's startup warning is near-verbatim), `communications.md`'s backoff correction and outbound-only narrative, `storage.md`'s no-presigned-URL principle.

### Task 8: Final sweep

Assert no `dotnet`, `Vantigo.slnx`, `global.json`, `AppHost` or `ConnectionStrings__` reference survives outside `docs/superpowers/**` and git history. Run the full gate — Go and frontend — and report each with working directory and tool versions.
