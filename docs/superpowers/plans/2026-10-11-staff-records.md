# Staff phase 1, delivery A2 — Records: implementation plan

> **For agentic workers:** implement this plan task by task, one implementer per task and a reviewer after it, never in the same context. Steps use checkbox (`- [ ]`) syntax for tracking. This revision carries the pre-flight of 2026-10-11 (two blockers, sixteen major, fourteen minor — all taken; its answers are in "The pre-flight's answers").

**Goal:** The records that make the register a personnel file and keep it lawful: a document archive per person with categories and retention classes; CSV import and export of the register; the payroll export behind a port; the person's own data exported; the retention run that erases per class and finishes; the dashboard's figures and attention items for Staff.

**Architecture:** Delivery A2 of the `staff` module (`apps/server/internal/staff`, schema `staff`, `openapi/staff.yaml`, `apps/staff/frontend`), on top of A1 as merged in PR #135 (main `53ab282c`). One migration for this delivery, `000NN_staff_records.sql` (the next free number when Task 1 lands; 00043 today, Invoices 4C may take it first): `document_categories`, `documents`, `object_deletions` — **no column is added to `people` or `settings`**; the retention and threshold columns reach the contract now and the `retention` block is derived. The module gains its first object-store use (scope `staff`), its first worker (`staff-retention`), its first config keys and its `Workers` slot. Absence (B) and accounts (C) are NOT in this plan: the payroll export ships without leave and absence columns, `/stats` without the absence figures, attention without the absence and account items, and health documents follow an end-of-employment schedule until B attaches them to a sick case.

**Tech stack:** as A1.

**Spec:** `docs/superpowers/specs/2026-10-11-staff-foundation-design.md` (revision 4, the A2 pre-flight's amendments marked) — delivery A2: §1 (A2), S14, S15, S16, S18, S19, S20, S21, §3.1 (the class column), §3.6 (`documents`, `document_categories`, `object_deletions`, the `retention` block, the document events), §4 Erase and Locking, §5, §6 (Documents, Data, Dashboard, People's `/personal-data`, `/legal-hold`, `/reassessed`, `/similar-erased`, Me's `/documents` and `/export`, Settings' `/thresholds/{key}/acknowledge`), §7, §8.5–8.7, §9, §10, §11 readings 9, 10, 31, 35. ## Readings of the spec

1. **The object store is a call out like the directory** (three accessors under the hook); the object written before the transaction and removed after a refusal.
2. **At most 200 documents per person**; the count leaks that hidden documents exist to a manage-only reader — accepted and documented.
3. **(pre-flight) Health documents are deleted `healthRetentionDays` after the last employment's end** until B attaches them to a case; current staff's are kept until B.
4. **(pre-flight) The A erase is per employment**, nulling its pay columns, deleting its A documents and blanking the A fields of its events, so a rehired person's old pay goes while they work again.
5. **A signed contract document sets `contract_signed_at`** when exactly one employment covers its date and has none; typing the date stays possible; the employment is locked before the document.
6. **A rehire is `POST /people/{id}/employments` on the erased record**, clearing `erased_at`; the creation form warns through `POST /people/similar-erased`.
7. **(pre-flight) The read-only rule's exceptions**: the hold, the reassessment, the unlink, the rehire; reads stay open.
8. **(pre-flight) The `retention` block on `GET /settings` is derived** from the ledger and the events; no column.
9. **The import creates the first employment from optional columns on create only**; an update never touches employments; export-only columns are ignored so a file the export wrote re-imports.
10. **The export never carries the sealed values**; `nationalIdOnFile` is yes/no.
11. **`people_imported` and `people_exported` are installation events** — a departure from customers' "no batch event", because S21 asks for every export to be an event.
12. **The payroll CSV's headers are sentence-case English**, the codes Skatteetaten's; B's columns are appended to the right.
13. **The `payroll_exported` event carries the SHA-256** of the file.
14. **The personal-data export is one in-memory JSON document**, never refused for size (a test with a few thousand events shows it fits).
15. **(pre-flight) The HR export is an audited reveal** (`personal_data_exported`); `/me/export` omits the sealed values and HR's notes, its events shaped as Self's (spec reading 35, for the owner).
16. **(pre-flight) The reassessment is due at the last employment's end + 12 months**, for an erased person not yet reassessed.
17. **(pre-flight) The OTP test without an owner flag**: one at ≥ 75 %, two, or ≥ 20 % positions summing to two årsverk; the item names the owner exception.
18. **(pre-flight) A threshold is acknowledged once and permanently**, as an event.
19. **The worker's "once per civil day" is idempotence**; the ledger runs every poll.
20. **(pre-flight) Two connection disciplines**: the erase on the lease's connection, the ledger with none held.
21. **Document rows are deleted, never marked**; a delete and an erase both insert the ledger row in the same transaction.
22. **Deleting by hand and erasing share one path**; the hand delete makes one attempt after commit and clears the ledger row on success.
23. **The migration number is the next free when Task 1 lands.**
