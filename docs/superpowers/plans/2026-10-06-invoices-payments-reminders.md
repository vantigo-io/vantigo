- **The lock rule (D18, MB rule 10's restatement):** *no call that takes its own connection or leaves the process while a transaction holds locks.* A directory read takes a second pool connection; an object-store call and an SMTP send leave the process; none is ever made inside `withLockedTx` (`inv/server.go:115`), and each goes through `contractscalls.go` and `noteContractCall` — the harness fails a test on a locked call (`inv/harness_test.go:92-130`). Whatever a decision under a lock needs from a directory is read before the transaction.
- **The lock order (D18, as amended by revision 3):** *own row first, then invoices in descending id, never the reverse.* A bank import: the file's account rows (account order), then the inserts. A match: the bank line `FOR UPDATE`, then its invoice (`LockInvoice`). The queue's apply and handle-reversal: the line, then its invoices in descending id. Dismiss, confirm-duplicate, treat-as-distinct, reopen: the line alone. A charge payment, a waiver, a manual delivery and its removal: the invoice alone (the children's parent triggers share it). A hold, a lift, a hand-off and its withdrawal: the invoice, then its letters. A run's item, the worker's dispatch, a print batch's letter: the invoice, then the letter. A batch posted or reprinted: the batch row `FOR NO KEY UPDATE`, then its letters' invoices in descending id, then the letters. A letter's withdraw or retry: the letter alone. A policy `PUT`: the customer's documents `FOR SHARE` newest first, then the policy row (reading 11); the merge: the documents (`LockCustomerDocuments`), then the policy rows by customer id ascending. **No path locks an invoice and then a bank line, an account row or a print batch** — with **one named exception**: the erase (Task 14), holding the person's documents, blanks the `resolution_note` of bank lines linked to the person's payments, **only `resolved` lines with a non-empty note**, which no path locks before an invoice (`apply` and `handle-reversal` take `exception` lines; `reopen` takes the line alone), so no cycle forms (reading 54). Every new lock is taken through `inv/locks.go`'s helpers, which report to the lock-order seam (Task 1).
- **The clock rule:** every request and every worker claim reads `s.deps.Clock()` **once** and derives its Oslo day with `businessDay` (`inv/values.go:32-35`, which answers **UTC midnight of the Oslo calendar day**); the import, each queue action, a run (one read for the whole run), each dispatch claim, a print batch, the posted confirmation, the overdue list and the attention items each have one `now` and one `today`. Every new query takes `@now` or `@today` as a parameter — never `now()` or `CURRENT_DATE`. The engine receives its day `L` and never reads a clock.
- **Exact decimal:** `big.Rat` and `numeric` inside; decimal text across every DTO; JSON numbers on the wire; amounts compared by value (`big.Rat.Cmp`, SQL numeric equality), never as text. A bank file's amounts are parsed to øre (`int64`) inside `bankfile` only — the OCR file speaks øre, a camt amount is refused past two decimals — and leave it as `numeric(14,2)`; the fingerprint hashes the øre with its sign. Rounding: a fee to the krone, .50 up (R8); interest summed exactly and rounded to øre once, half away from zero (D8).
- **One refusal shape:** 400s through `invalid(title, errs)` on the field (`inv/errors.go:60`), the file's on `file`; 409s through `conflict(code, title, detail)` (`inv/errors.go:43`) — `InvoicesConflictProblem.code` is a **free string** (`openapi/invoices.yaml:157-159`) whose codes the schema's `description` lists, and **Task 1 lands every PR 1 code in that description and every PR 1 extra field** (`bankFileId`, `uploadedAt`, `uploadedBy`, `chargesOutstanding`, `kind`, `halfYear`, `lastBookedOn`, and `invoiceId` beside `openAmount` on `payment_exceeds_open` — D5), so no later task edits that single YAML line; a refusal decided under a lock rolls the transaction back (`errRefused`).

Tests run `t.Parallel()` as the house does, **except** a test that installs a package-level seam (`export_test.go`'s `Set…` hooks) and every race test — those never run in parallel (the hooks are the package's). The OCR rules are D3 step 3's, every one: 80 characters after CR/LF are stripped, `NY`; the grammar `10 (20 (30 31 [32])+ 88)+ 89`; items 2/3 sharing item 1's transaction number and type, item 3 iff type 20/21; per assignment and per transmission the transaction count, the record count (start and end records included), the **signed** sum (a `-` subtracts; types 18/20 add) and the first and last settlement date against `88`/`89`; service code 09 only; DDMMYY with the century 2000–2099; KID digits with a trailing `-` allowed; item-3 text decoded as ISO-8859-1 leniently; every booking date on or before `today` and not before 2000-01-01; at most `MaxTransactions`. Types 10–17 become transactions; 18–21 are counted `card_information` (still checked and summed). `Accounts` holds every `Oppdragskonto` normalised; a non-normalisable account is an `*Error`. `Identity` is `Dataavsender:Forsendelsesnummer:Datamottaker`. ## Readings of the spec

Each is a choice the spec leaves open, or a place where two of its passages cannot both be built, decided here for the user's verdict. Readings first marked **(pre-flight)** were answered by the pre-flight; each now says its outcome, and "The pre-flight's answers" below lists them. Readings 46–54 were added by the pre-flight's revision.

1. **One migration, `00041_invoices_receivables.sql`, owned by Task 1 and amended in place by the protocol in Global Constraints**, carries every PR 1 table (Phasing names `00041` for PR 1 and `00042` for PR 2); one file per schema is the scanner's rule, and PR 1 touches only the invoices schema — **customers' schema needs nothing** (D7's policy is an invoices table). Its tests live in their own file, `srv/db/schema_invoices_receivables_test.go`; `schema_test.go` changes only the reserved-word test's version.
2. **The engine and the parsers are packages, not files**: `inv/reminderrules` (the spec's `inv/reminderrules.go`) and `inv/bankfile`, each a leaf whose purity a test enforces, so "one pure function the four callers share" (D8) cannot quietly read the store; the server's `ruleinput.go` is the only door into the engine.
3. **Counts on immutable rows written before what they count** (accepted at the pre-flight). `bank_files.duplicates` is known only after the `ON CONFLICT` insert, and `reminder_runs.letters`/`skipped` only after the run's last item, while both rows must precede the rows that reference them and both tables are immutable. Each such count is **nullable and set once from NULL** by the request that inserted the row (the triggers allow exactly that, the house's "set once" shape); `bank_files.duplicates` is set inside the import's own transaction, so no reader ever sees it NULL, and it equals `count(*) … duplicate_of_id IS NOT NULL` (frozen); a crash mid-run leaves the run's counts NULL and the API then answers its letters by count and its `skipped` as absent. `bank_files` also gains **`ignored_kinds jsonb`** with `CHECK (jsonb_typeof(ignored_kinds) = 'object')`, so the file's page shows the by-kind breakdown the 201 shows.
4. **The release's rate seed is a function**, `invoices.seed_collection_rate(…)`, holding D6's `ON CONFLICT … DO UPDATE SET release_value …` rule; `00041` calls it for every seed and every later release's migration calls it, so `TestCollectionRates_ReleaseSeedOverUserRow` tests the statement a release will run.
5. **(pre-flight) "Outdated" is any half-year a letter needs without a row starting on its first day** — each half-year of the interest period, and the letter's own for the compensation — so a gap between rows and a half-year before the first row refuse too, where D6's words ("the latest row … starts before the current half-year") would silently carry an old rate across a missing half-year.
6. **(pre-flight) A rate row is "used"** when a letter with facts (printed or sent) is dated on or after its `valid_from` and before the next row of its kind; such a row is not `usable` and its `DELETE` is refused `collection_rate_in_force` like an in-force one — a paper letter printed for a `postOn` up to seven days ahead can rely on a row not yet in force.
7. **A credit note lowers interest from its own day; a payment from the day after** (the pre-flight overturned this plan's first reading, restoring the spec's reading 5 and the user's I7 decision). Day `d` bears gross − the credit notes issued on or before `d` − the live payments paid on or before `d − 1`; spec D8's `open(d − 1)` gloss is amended to say so (revision 3). Pinned: 10 000 due Monday 15 Jun 2026, `L` 15 Jul — a 4 000 credit note issued 5 Jul → **84.89**; a 4 000 payment paid 5 Jul → **86.23**. It is also the debtor-favourable reading the design takes elsewhere (m5, reading 32).
8. **(pre-flight) The allocation within charges is recomputed**, over every live charge payment in (`paid_on`, id) order, against the sent letters' fees and compensation net of waivers oldest first, then interest (the latest letter's cumulative interest less interest waivers); what is left is `refundDue`. A letter freezes the allocation's figures as they stood when it was sent — "of the time" (D9) read that way.
9. **Holds, hand-offs and anonymisation withdraw `queued`, `awaiting_print` and `failed` letters — not `printed` ones, nor one being sent** (accepted at the pre-flight; spec D11 and D19 amended). D11 listed `printed`, but NI4's re-judge and `TestPrintBatch_PostedRejudges` need a printed letter of an invoice held or handed off since printing to survive until the posting confirmation, which sends it with its fee waived `claimed_in_error` — paper may already be in the post, and a withdrawn record of a mailed letter would be false. `failed` is withdrawn although D11 omitted it: D8 counts it in flight, and a retry would otherwise revive it. **The four conditions:** (a) the hold's, the lift's and the hand-off's answers (`lettersLeft`) and screens name the printed letters left, so a person can pull them and withdraw them by hand, and the erase logs them; (b) the posting skips a letter withdrawn since printing; (c) the batch's combined PDF renders only `printed` and `sent` letters; (d) Task 1's triggers let the erase blank every letter's recipient.
10. **The hand-off of an undelivered invoice is a guarded refusal**: 409 **`invoice_not_delivered`** unless `acknowledgeNotDelivered: true` (the `acknowledgeStaleImport` pattern; spec D11/D21 amended). The hand-off records what was already done outside Vantigo, and refusing to record it would keep Vantigo dunning a debtor whose claim sits with an agency; NI3 and FinKN 2017-492 are served by the friction, and the detail says to record a manual delivery first if the invoice was in fact delivered.
11. **The policy `PUT` locks the customer's documents first** — `FOR SHARE`, newest first — checks under that lock that the customer has documents and is not anonymised (`erased_customers`, else 404), then locks the policy row (spec D7/D18 amended). D18's "a policy `PUT` | the policy row" alone would let a `PUT` that saw documents on the pool insert a row after the merge's `lockPolicies` found none — an orphan for the merged-away customer; with the share lock, READ COMMITTED's re-check after the merge commits finds no documents (404). Share-locking newest first matches `LockCustomerDocuments` and every invoice-only path, so no new cycle forms. `TestPolicy_MergeRacesPolicyPut` pins it.
12. **(pre-flight) Two read operations beyond D21**: `getInvoicesReminders` (`?status=&channel=&invoiceId=&runId=`, paged) and `getInvoicesReminderPrintBatches` (`?posted=`, paged) — the paper page must list the letters awaiting print and the unposted batches, and the run page and the failed-letter attention item need letters by run and by status.
13. **The document answers `chargePayments`** beside `charges` (D21 names `charges` and `waivers` only): a charge payment's removal needs its id, as the payments do.
14. **A letter's language** is the buyer snapshot's `buyer_language` when it is `en`, otherwise `nb` (the column is nullable, `mig/00034…:142`; `reminders.language` is NOT NULL).
15. **Letter goldens are of the letter's text**, per level and language, read through a `SetReminderPDFModelText` hook into `inv/testdata/reminders/*.txt` with `-update`, because text diffs review well; **the PDF itself is reproducible** — `WithCreationDate(sent_on)`, as the invoice PDF's `WithCreationDate(m.created)` (`inv/pdf.go:498`; "the render is reproducible", `pdfstore.go:256-259`) — and a test asserts the same row renders the same bytes and the stored hash is the rendered one. (The first revision's premise that maroto writes its creation time was wrong.)
16. **At most one letter a second**: each 5-second cycle handles up to five letters, one at a time.
17. **An outdated or unreviewed reschedule touches neither `attempts` nor `first_attempt_at`**, so it never runs into the 48-hour `failed` rule (I11's "not counted").
18. **The reminder send reports as `SMTPSend`** through the existing `smtpSend` (`inv/contractscalls.go:184`); the spec's `smtp.reminder` is the same call.
19. **Accounts compared digits-only, 11 long**: a NO IBAN is reduced to its BBAN after its mod-97 check; a foreign IBAN, or an account that is not 11 digits, is `bank_account_unknown`.
20. **Detection drops a UTF-8 BOM**, reads the first non-blank line for OCR, and reads only the root element for camt; anything else is the 400 "Not an OCR giro or camt.054 file".
21. **OCR card information (types 18–21) is checked and summed but ignored**, counted `card_information`; a service code other than 09 refuses the file (D3: "service code 09 only").
22. **A camt `DBIT` reversal** becomes one transaction per `TxDtls` (or the entry), `direction = debit`, queued `reversal`; a plain `DBIT` is ignored `debit`.
23. **The remittance text** is camt's `Ustrd` lines joined by a space, else the entry's `AddtlNtryInf`, else OCR's item-3 text, cut to 1 000; the fingerprint uses the KID when present, else this text normalised.
24. **`suggested_invoice_id`** is written when a line is queued (by the match or a reopen) if exactly one suggestion exists; the suggestions themselves are recomputed on every `GET`.
25. **`line_ref`**: OCR `<oppdragsnummer>/<transaksjonsnummer>`; camt `<Ntfctn/Id>/<entry n>/<tx n>`, 1-based.
26. **A run's page** is the run row and its letters with their current status; skipped items are answered by the run's 201 only (the row keeps a count).
27. **The run's refusals are judged on a pool pre-pass** over its items before the run row is written; under each item's lock the engine judges again, and an outcome that changed — including one newly outdated or unreviewed — is skipped `action_changed`.
28. **Stale** is `lastBookedOn < today − stale_import_days`, and always when no file was ever imported (m8).
